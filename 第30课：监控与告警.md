## 2. Prometheus 指标采集

### 2.1 FastAPI 集成 prometheus-client

```python
from prometheus_client import Counter, Histogram, generate_latest
from fastapi import Response

# 定义指标
REQUEST_COUNT = Counter(
    "carabot_requests_total",
    "Total request count",
    ["method", "endpoint", "status"],
)
REQUEST_DURATION = Histogram(
    "carabot_request_duration_seconds",
    "Request duration in seconds",
    ["method", "endpoint"],
)
SEARCH_RESULTS = Histogram(
    "carabot_search_results_count",
    "Number of search results returned",
    buckets=[0, 1, 3, 5, 10, 20],
)
AGENT_TOOL_CALLS = Counter(
    "carabot_agent_tool_calls_total",
    "Total tool call count",
    ["tool_name"],
)

# 指标暴露端点
@router.get("/metrics")
async def metrics():
    return Response(content=generate_latest(), media_type="text/plain")
```

### 2.2 在中间件中记录指标

```python
class MetricsMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        start = time.time()
        response = await call_next(request)

        REQUEST_COUNT.labels(
            method=request.method,
            endpoint=request.url.path,
            status=response.status_code,
        ).inc()

        REQUEST_DURATION.labels(
            method=request.method,
            endpoint=request.url.path,
        ).observe(time.time() - start)

        return response
```

### 2.3 Prometheus 配置

```yaml
# prometheus.yml
scrape_configs:
  - job_name: 'carabot'
    scrape_interval: 15s
    static_configs:
      - targets: ['carabot:8000']
    metrics_path: '/metrics'
```

### 2.4 关键告警规则

```yaml
# alerts.yml
groups:
  - name: carabot
    rules:
      - alert: HighErrorRate
        expr: rate(carabot_requests_total{status="500"}[5m]) > 0.05
        annotations:
          summary: "High error rate: {{ $value }}"

      - alert: SlowRequests
        expr: histogram_quantile(0.95, carabot_request_duration_seconds) > 3
        annotations:
          summary: "P95 latency > 3s"

      - alert: ServiceDown
        expr: up{job="carabot"} == 0
        annotations:
          summary: "CaraBot service is down"
```

## 3. Agent 调用链追踪

### 3.1 LangSmith / LangFuse

```python
# LangSmith 集成（零侵入）
import os
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = "ls_..."
os.environ["LANGCHAIN_PROJECT"] = "carabot"

# LangGraph 的每次 astream_events / ainvoke 都会自动上报
# 在 LangSmith UI 中可以看到完整的：
#   - Agent 推理步骤
#   - 工具调用的输入/输出
#   - LLM token 消耗
#   - 每个步骤的耗时
```

### 3.2 追踪的价值

```
一次慢请求的追踪分析：
  call_model (2500ms)            ← LLM API 调用慢
    ├── System prompt: 200 tokens
    ├── Conversation history: 1200 tokens
    └── Tool results: 3500 tokens  ← 上下文太大！
  call_tools (120ms)
    ├── search_knowledge_base (95ms)
    └── get_knowledge_base_stats (25ms)
  call_model (1800ms)
    └── Final answer generation

结论：上下文 (200+1200+3500=4900 tokens) 导致 LLM 推理变慢
优化：减少每次传给 LLM 的历史消息条数
```

## 4. Grafana 仪表板

### 4.1 推荐的 Dashboard Panels

| Panel | 指标 | 类型 |
|-------|------|------|
| QPS | `rate(carabot_requests_total[1m])` | 时序折线图 |
| P50/P95/P99 延迟 | `histogram_quantile(0.5/0.95/0.99, ...)` | 时序折线图 |
| 错误率 | `rate(carabot_requests_total{status=~"5.."}[5m])` | 时序折线图 |
| 工具调用分布 | `carabot_agent_tool_calls_total` | 饼图 |
| 搜索结果数分布 | `carabot_search_results_count` | 热力图 |
| 组件健康状态 | `up` 指标 | 状态面板 |
