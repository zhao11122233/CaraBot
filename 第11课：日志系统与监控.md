## 1. 结构化日志 vs 传统日志

### 1.1 传统文本日志

```
2024-03-15 10:30:45 INFO UploadService: Uploaded file test.pdf, 23 chunks
2024-03-15 10:30:46 ERROR SearchService: Embedding failed: CUDA out of memory
```

**问题**：机器难以解析。想知道 "过去 1 小时有多少次 Embedding 失败？" 需要用正则去 grep，很不靠谱。

### 1.2 结构化 JSON 日志

```json
{"timestamp":"2024-03-15T10:30:45.123Z","level":"INFO","logger":"src.app.services.upload_service","module":"upload_service:130","message":"Upload complete: doc_id=abc123..., file='test.pdf', chunks=23","trace_id":"a1b2c3d4-..."}
{"timestamp":"2024-03-15T10:30:46.456Z","level":"ERROR","logger":"src.app.services.search_service","module":"search_service:45","message":"Embedding failed: CUDA out of memory","trace_id":"e5f6g7h8-...","exception":"Traceback..."}
```

**好处**：每条日志是一个 JSON 对象，ELK/Grafana 可以直接索引和分析：
```bash
# 用 jq 分析 JSON 日志
cat carabot.log | jq 'select(.level == "ERROR") | {timestamp, message, trace_id}'
cat carabot.log | jq 'group_by(.logger) | map({logger: .[0].logger, count: length})'
```

## 2. CaraBot 的日志系统

### 2.1 两种日志格式

CaraBot 支持 JSON 和文本两种格式，通过 `.env` 配置切换：

```bash
# 生产环境：JSON 格式（便于 ELK 采集）
LOG_FORMAT=json

# 开发环境：文本格式（便于肉眼阅读）
LOG_FORMAT=text
```

### 2.2 JSONFormatter 实现

```python
class JSONFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        log_entry = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "module": f"{record.module}:{record.lineno}",
            "message": record.getMessage(),
            "trace_id": get_trace_id(),          # 自动注入 trace_id
        }
        if record.exc_info and record.exc_info[0]:
            log_entry["exception"] = self.formatException(record.exc_info)

        return json.dumps(log_entry, ensure_ascii=False, default=str)
```

**每个日志条目都自动包含**：
- `timestamp`：ISO 8601 格式，带时区
- `level`：DEBUG / INFO / WARNING / ERROR
- `logger`：完整的模块路径
- `module`：文件名:行号
- `trace_id`：关联到具体请求
- `exception`：异常堆栈（如果有）

### 2.3 TextFormatter 实现

```python
class TextFormatter(logging.Formatter):
    def __init__(self):
        super().__init__(
            "%(asctime)s | %(levelname)-8s | %(name)s | %(module)s:%(lineno)d | "
            "trace_id=%(trace_id)s | %(message)s",
            datefmt="%Y-%m-%dT%H:%M:%S",
        )

    def format(self, record):
        record.trace_id = get_trace_id()
        return super().format(record)
```

输出示例：
```
2024-03-15T10:30:45 | INFO     | src.app.services.upload_service | upload_service:130 | trace_id=a1b2c3d4 | Upload complete: doc_id=abc, file='test.pdf', chunks=23
```

### 2.4 日志配置初始化

```python
def setup_logging(settings: Settings):
    root = logging.getLogger()
    root.setLevel(getattr(logging, settings.log_level))

    # 清除已有的 handler（防止重复）
    root.handlers.clear()

    # 选择格式器
    formatter = JSONFormatter() if settings.log_format == "json" else TextFormatter()

    # 控制台输出
    console_handler = logging.StreamHandler(sys.stdout)
    console_handler.setFormatter(formatter)
    root.addHandler(console_handler)

    # 文件输出
    os.makedirs(os.path.dirname(settings.log_file), exist_ok=True)
    file_handler = logging.FileHandler(settings.log_file, encoding="utf-8")
    file_handler.setFormatter(formatter)
    root.addHandler(file_handler)

    # 降低第三方库的日志噪音
    for noisy in ("asyncio", "urllib3", "botocore", "httpx", "chromadb", "pymilvus"):
        logging.getLogger(noisy).setLevel(logging.WARNING)
```

## 3. trace_id 全链路追踪

### 3.1 什么是全链路追踪？

一个用户请求可能经过多个服务、多次数据库调用。trace_id 把这些分散的日志串联起来。

```
用户 → POST /api/v1/chat  (trace_id = "abc123")
  │
  ├── [abc123] INFO  RequestLoggingMiddleware: POST /api/v1/chat
  ├── [abc123] INFO  AuthGuard: API key validated
  ├── [abc123] INFO  AgentService: Agent started, thread_id=xxx
  │     ├── [abc123] INFO  AgentService: Tool call: search_knowledge_base
  │     ├── [abc123] INFO  SearchService: Search: query='什么是RAG', found=5, time=45ms
  │     └── [abc123] INFO  ChromaStore: Collection 'carabot_knowledge' queried
  ├── [abc123] INFO  AgentService: Agent completed, 2 tool calls
  └── [abc123] INFO  RequestLoggingMiddleware: POST /api/v1/chat → 200 (1523ms)
```

### 3.2 实现原理：contextvars

```python
from contextvars import ContextVar

_trace_id_var: ContextVar[str] = ContextVar("trace_id", default="")

def set_trace_id(trace_id=None) -> str:
    tid = trace_id or str(uuid.uuid4())
    _trace_id_var.set(tid)
    return tid

def get_trace_id() -> str:
    return _trace_id_var.get()
```

**关键**：`ContextVar` 是协程安全的。同一个请求的所有操作都在同一个协程中，所以 `get_trace_id()` 拿到的都是同一个值。不同请求在不同协程中，互不干扰。

### 3.3 两种使用方式

```python
# 方式一：日志自动注入（推荐）
# JSONFormatter 内部调用 get_trace_id()，每条日志自动带上
logger.info("Agent completed, 2 tool calls")

# 方式二：手动获取
trace_id = get_trace_id()
response.headers["X-Trace-ID"] = trace_id  # 返回给前端
```

### 3.4 排查生产问题的实战流程

1. **用户反馈问题，提供了 X-Trace-ID**
2. **在 ELK 中搜索这个 trace_id**
3. **看到完整的请求链路**：哪个步骤耗时最长？哪个步骤报错了？
4. **定位根因**：比如 "Embedding failed: CUDA out of memory" → GPU 显存不足

## 4. 健康检查：组件级监控

### 4.1 /health 接口

```python
@router.get("/health")
async def health_check(...):
    return {
        "status": "healthy",  # 或 "degraded" / "unhealthy"
        "components": {
            "database": "ok",
            "vector_store": "ok",
            "embedding_model": "ok",
            "redis": "ok",         # 或 "unavailable"
            "agent": "ok",
        },
        "uptime_seconds": 3600,
    }
```

### 4.2 启动时的健康检查

在 `create_app()` 的 lifespan 中：

```python
async def lifespan(app: FastAPI):
    errors = []

    # 检查数据库
    try:
        async with session_factory() as session:
            await session.execute(text("SELECT 1"))   # 最轻量级的查询
        logger.info("  [OK] Database connection verified")
    except Exception as exc:
        errors.append(f"Database: {exc}")

    # 检查向量存储
    try:
        vs_ok = await vector_store.health_check()
        if vs_ok:
            logger.info("  [OK] Vector store connected")
        else:
            errors.append("Vector store: unreachable")
    except Exception as exc:
        errors.append(f"Vector store: {exc}")

    # 检查嵌入模型
    try:
        await embedding_service.startup()
        logger.info("  [OK] Embedding model loaded")
    except Exception as exc:
        errors.append(f"Embedding model: {exc}")

    # 检查 Redis（可选，不阻塞启动）
    try:
        r = aioredis.from_url(settings.redis_url)
        await r.ping()
        logger.info("  [OK] Redis connected")
    except Exception:
        logger.warning("  [WARN] Redis not available")

    # ...检查 Agent 服务
```

### 4.3 健康检查的设计原则

| 原则 | 说明 |
|------|------|
| **快速失败** | 关键组件（数据库、向量库）失败时明确报错 |
| **优雅降级** | 非关键组件（Redis）不可用时继续运行 |
| **轻量检查** | 用 `SELECT 1` 而不是 `COUNT(*)`，用 `ping()` 而不是读写数据 |
| **完整覆盖** | 每个外部依赖都有对应的检查项 |
| **不要阻塞** | 一个组件的检查失败不阻塞其他组件的检查 |

### 4.4 各组件健康检查实现

```python
# 数据库
async with session_factory() as session:
    await session.execute(text("SELECT 1"))

# 向量存储 (Chroma)
def health_check(self):
    try:
        self._get_client()
        return True
    except Exception:
        return False

# 向量存储 (Milvus)
async def health_check(self):
    try:
        await self._ensure_connected()
        return utility.get_server_version() is not None
    except Exception:
        return False

# 嵌入模型
async def health_check(self):
    if self._model is None:
        return False
    try:
        _ = await self.embed_query("health check")
        return True
    except Exception:
        return False
```

## 5. 日志级别使用规范

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| **DEBUG** | 开发调试，变量值、中间状态 | `logger.debug("Query embedding shape: %s", shape)` |
| **INFO** | 关键业务流程节点 | `logger.info("Upload complete: doc_id=%s, file='%s'", doc_id, filename)` |
| **WARNING** | 异常但不影响主流程 | `logger.warning("Redis not available, skipping cache")` |
| **ERROR** | 业务异常，需要关注 | `logger.error("Embedding failed for doc_id=%s: %s", doc_id, exc)` |
| **CRITICAL** | 系统级故障 | `logger.critical("Database connection pool exhausted")` |

### 日志消息写法：结构化

```python
# ❌ 不推荐：用 f-string（丢失了结构化信息）
logger.info(f"Upload complete: doc_id={doc_id}, file='{filename}', chunks={n}")

# ✅ 推荐：用 % 格式化（日志系统可以按参数索引和过滤）
logger.info("Upload complete: doc_id=%s, file='%s', chunks=%d", doc_id, filename, n)
```

## 6. 实践：添加请求耗时统计

### 需求

记录每个请求的耗时分布，帮助发现慢请求。

### 实现：在日志中间件中添加耗时

```python
class RequestLoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        start = time.perf_counter()
        response = await call_next(request)
        duration_ms = (time.perf_counter() - start) * 1000

        # 慢请求告警
        if duration_ms > 3000:
            logger.warning(
                "SLOW REQUEST: %s %s took %.0fms",
                request.method, request.url.path, duration_ms,
            )

        logger.info(
            "%s %s → %d (%.1fms)",
            request.method, request.url.path, response.status_code, duration_ms,
        )
        return response
```
