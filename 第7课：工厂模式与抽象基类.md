## 1. 问题驱动：为什么需要抽象？

### 1.1 场景：支持两种向量数据库

CaraBot 需要同时支持 Milvus（生产环境）和 Chroma（开发环境）。

**❌ 不用抽象的做法**：代码里到处都是 if-else：

```python
# 糟糕的设计：每个使用向量存储的地方都要判断
async def search(query):
    if settings.vector_store_type == "milvus":
        results = await milvus_search(query)  # Milvus 的 API
    elif settings.vector_store_type == "chroma":
        results = await chroma_search(query)  # Chroma 的 API（参数不同！）
    # 将来再加 Qdrant？再加 Pinecone？这里的 if-else 会爆炸
```

**问题**：
- 每加一个新的向量数据库，要改几十处 if-else
- 不同的数据库 API 完全不同（参数名、返回值格式都不同）
- 调用方必须知道所有数据库的细节

**✅ 用抽象的做法**：定义一个统一的"合同"，所有数据库都签这份合同：

```python
# 调用方不需要知道底层是什么数据库
async def search(query):
    results = await vector_store.search(query_embedding, top_k=5)  # 统一接口！
```

## 2. 抽象基类：定义契约

### 2.1 什么是抽象基类？

抽象基类 = 一份**合同**（interface/contract），它只定义"必须有哪些方法"，不写具体实现。所有子类必须实现这些方法。

### 2.2 CaraBot 的 BaseVectorStore

```python
from abc import ABC, abstractmethod
from langchain_core.documents import Document

class BaseVectorStore(ABC):
    """所有向量存储必须实现的统一接口"""

    @abstractmethod
    async def add_documents(
        self, documents: list[Document], collection: str | None = None,
        embeddings: list[list[float]] | None = None,
    ) -> list[str]:
        """存入文档 → 返回 chunk IDs"""
        ...  # 没有实现体！子类必须写

    @abstractmethod
    async def search(
        self, query_embedding: list[float], top_k: int = 5,
        collection: str | None = None, threshold: float | None = None,
    ) -> list[tuple[Document, float]]:
        """向量检索 → 返回 [(文档, 相似度分数), ...]"""
        ...

    @abstractmethod
    async def delete(
        self, doc_ids: list[str], collection: str | None = None
    ) -> int:
        """删除文档 → 返回删除数量"""
        ...

    @abstractmethod
    async def health_check(self) -> bool:
        """健康检查 → 返回是否可用"""
        ...

    @abstractmethod
    async def get_collection_stats(self, collection: str | None = None) -> dict:
        """获取统计信息"""
        ...
```

**关键点**：
- `ABC` 作为基类：告诉 Python 这是一个抽象类，不能直接实例化
- `@abstractmethod`：标记必须实现的方法
- `...`（ellipsis）：表示"这里没有实现，等子类来填"
- 类型注解完整：调用方看这个接口就知道传什么参数、返回什么

### 2.3 如果子类忘了实现某个方法？

```python
class BrokenStore(BaseVectorStore):
    pass

store = BrokenStore()  # ❌ TypeError: Can't instantiate abstract class
                       #    BrokenStore with abstract methods add_documents,
                       #    delete, get_collection_stats, health_check, search
```

Python 在**实例化时**就报错，不会等到运行时才发现。

## 3. 多态：一份调用代码，两种实现

### 3.1 ChromaStore：开发环境的实现

```python
class ChromaStore(BaseVectorStore):
    def __init__(self, settings: Settings):
        self._persist_dir = settings.chroma_persist_dir
        self._default_collection = settings.chroma_collection_name
        self._client = None

    async def add_documents(self, documents, collection=None, embeddings=None):
        col = self._get_or_create_collection(collection or self._default_collection)

        chunk_ids, texts, metadatas = [], [], []
        for doc in documents:
            cid = str(uuid.uuid4())
            chunk_ids.append(cid)
            texts.append(doc.page_content)
            metadatas.append({**doc.metadata, "chunk_id": cid})

        col.add(documents=texts, metadatas=metadatas, ids=chunk_ids, embeddings=embeddings)
        return chunk_ids

    async def search(self, query_embedding, top_k=5, collection=None, threshold=None):
        col_name = collection or self._default_collection
        col = self._get_or_create_collection(col_name)

        results = col.query(
            query_embeddings=[query_embedding],
            n_results=top_k,
            include=["documents", "metadatas", "distances"],
        )

        output = []
        for i, doc_id in enumerate(results["ids"][0]):
            distance = results["distances"][0][i]
            score = 1.0 - (distance / 2.0)  # Chroma 返回距离，我们要相似度
            if threshold is not None and score < threshold:
                continue
            doc = Document(
                page_content=results["documents"][0][i] or "",
                metadata=results["metadatas"][0][i] or {},
            )
            output.append((doc, score))
        return output
    # ... 其他方法实现
```

### 3.2 MilvusStore：生产环境的实现

```python
class MilvusStore(BaseVectorStore):
    def __init__(self, settings: Settings):
        self._host = settings.milvus_host
        self._port = settings.milvus_port
        self._default_collection = settings.milvus_collection_name
        self._dimension = settings.milvus_dimension
        self._connected = False

    async def add_documents(self, documents, collection=None, embeddings=None):
        await self._ensure_connected()
        col_name = collection or self._default_collection

        chunk_ids, data_rows = [], []
        for i, doc in enumerate(documents):
            chunk_id = str(uuid.uuid4())
            chunk_ids.append(chunk_id)
            data_rows.append({
                "id": chunk_id,
                "embedding": embeddings[i] if embeddings else [],
                "text": doc.page_content,
                "doc_id": doc.metadata.get("document_id", ""),
                "metadata": doc.metadata,
            })

        def _insert():
            col = self._get_collection(col_name)
            col.insert(data_rows)
            col.flush()

        await asyncio.to_thread(_insert)  # Milvus SDK 是同步的，用线程池包一下
        return chunk_ids

    async def search(self, query_embedding, top_k=5, collection=None, threshold=None):
        await self._ensure_connected()
        col_name = collection or self._default_collection

        def _search():
            col = self._get_collection(col_name)
            col.load()
            search_params = {"metric_type": "IP", "params": {"nprobe": 16}}
            results = col.search(
                data=[query_embedding],
                anns_field="embedding",
                param=search_params,
                limit=top_k,
                output_fields=["text", "doc_id", "metadata"],
            )
            return results[0]

        hits = await asyncio.to_thread(_search)

        results = []
        for hit in hits:
            score = float(hit.score)
            if threshold is not None and score < threshold:
                continue
            doc = Document(
                page_content=hit.entity.get("text", ""),
                metadata={
                    "chunk_id": hit.id,
                    "document_id": hit.entity.get("doc_id", ""),
                    **hit.entity.get("metadata", {}),
                },
            )
            results.append((doc, score))
        return results
    # ... 其他方法实现
```

### 3.3 关键观察

| 维度 | ChromaStore | MilvusStore |
|------|------------|-------------|
| 存储位置 | 本地文件 `./data/chroma/` | 远程服务器 `localhost:19530` |
| 连接方式 | `PersistentClient(path=...)` | `connections.connect(host=..., port=...)` |
| 搜索 API | `col.query(query_embeddings=...)` | `col.search(data=..., anns_field=..., param=...)` |
| 相似度计算 | Chroma 返回距离，需转换 `1 - distance/2` | Milvus 直接返回 IP 分数 |
| 删除方式 | 先查出 IDs 再 `col.delete(ids=...)` | 用表达式 `col.delete(expr=...)` |
| 同步/异步 | Chroma SDK 原生同步 | pymilvus 同步，用 `asyncio.to_thread` 包装 |

**尽管内部实现完全不同，对外接口一模一样！这就是多态的力量。**

## 4. 工厂模式：按配置创建实例

### 4.1 get_vector_store 工厂函数

```python
# src/app/vectorstore/__init__.py
from src.app.core.config import Settings
from src.app.vectorstore.base import BaseVectorStore
from src.app.vectorstore.chroma_store import ChromaStore
from src.app.vectorstore.milvus_store import MilvusStore

def get_vector_store(settings: Settings) -> BaseVectorStore:
    """工厂函数：根据配置创建对应的向量存储实例"""
    if settings.vector_store_type == "milvus":
        logger.info("Creating MilvusStore for production use")
        return MilvusStore(settings)
    elif settings.vector_store_type == "chroma":
        logger.info("Creating ChromaStore for local development")
        return ChromaStore(settings)
    else:
        raise ConfigurationException(
            f"Unknown vector_store_type: {settings.vector_store_type}. "
            f"Valid options: milvus, chroma"
        )
```

**返回类型是 `BaseVectorStore`**：调用方不需要知道具体是哪个实现。

### 4.2 工厂模式的三个要素

```
1. 统一的接口        ← BaseVectorStore（抽象基类）
2. 多种具体实现      ← ChromaStore, MilvusStore
3. 一个创建函数      ← get_vector_store(settings) → 根据配置选择
```

### 4.3 在 create_app 中使用工厂

```python
def create_app() -> FastAPI:
    settings = load_settings()

    # 一行配置决定整个应用的存储后端
    vector_store = get_vector_store(settings)
    # ↑ 可能是 MilvusStore，也可能是 ChromaStore
    # 后续代码完全不需要关心是哪个！

    search_service = SearchService(settings, embedding_service, vector_store)
    upload_service = UploadService(settings, doc_processor, embedding_service, vector_store, dedup_service)
    # ↑ 所有服务都接收 BaseVectorStore，不依赖具体实现
```

**改一行 `.env` 配置即可切换**：
```bash
# 开发环境
VECTOR_STORE_TYPE=chroma

# 生产环境
VECTOR_STORE_TYPE=milvus
```

## 5. 设计原则总结

### 5.1 依赖倒置原则（DIP）

> 高层模块不应该依赖低层模块，两者都应该依赖抽象。

```
❌ 错误：UploadService 直接依赖 MilvusStore
   UploadService → MilvusStore

✅ 正确：UploadService 依赖 BaseVectorStore（抽象）
   UploadService → BaseVectorStore ← MilvusStore
                                   ← ChromaStore
```

### 5.2 开闭原则（OCP）

> 对扩展开放，对修改关闭。

如果要加一个新的向量数据库（比如 Qdrant），只需要：
1. 新建 `qdrant_store.py`，实现 `BaseVectorStore`
2. 在 `get_vector_store()` 加一个 `elif`

**不需要修改任何现有服务代码！**

### 5.3 里氏替换原则（LSP）

> 子类必须能替换父类。

`SearchService` 持有 `BaseVectorStore` 类型的引用。传入 `ChromaStore` 能正常工作，传入 `MilvusStore` 也能正常工作。它们的行为符合基类定义的契约。
