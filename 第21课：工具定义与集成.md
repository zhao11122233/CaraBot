## 1. 工具的本质

### 1.1 工具 = 函数 + 说明书

工具不是一个新概念。它就是**一个带类型注解的 Python 函数**，加上 LLM 能理解的描述信息：

```python
# 普通 Python 函数
async def search_knowledge_base(query: str, top_k: int = 5) -> str:
    """搜索知识库"""
    ...

# 包装为 LLM 工具
# LangChain 自动生成给 LLM 的 JSON Schema：
{
  "name": "search_knowledge_base",
  "description": "Search the knowledge base for relevant document chunks.",
  "parameters": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "description": "Search query text"},
      "top_k": {"type": "integer", "default": 5, "description": "Number of results"},
      "threshold": {"type": "number", "default": 0.7, "description": "Min similarity"}
    },
    "required": ["query"]
  }
}
```

LLM 看到这个 Schema，就能自主决定：什么时候调用、传什么参数。

### 1.2 bind_tools：让 LLM 知道有哪些工具

```python
self._model = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.1,
    openai_api_key=settings.llm_api_key,
    openai_api_base=settings.llm_base_url,
)
self._model_with_tools = self._model.bind_tools(self._tools)
# bind_tools 把工具列表注入到每次 LLM 调用的请求中
```

## 2. CaraBot 的三个内置工具

### 2.1 search_knowledge_base（有参数工具）

```python
# ① 定义输入 Schema（Pydantic 模型）
class SearchToolInput(BaseModel):
    query: str = Field(..., description="Search query text")
    top_k: int = Field(default=5, description="Number of results to return")
    threshold: float = Field(default=0.7, description="Minimum similarity score")
    collection: str | None = Field(default=None, description="Collection name")

# ② 用 @tool 装饰器创建工具
@tool(args_schema=SearchToolInput)
async def search_knowledge_base(
    query: str, top_k: int = 5, threshold: float = 0.7, collection: str | None = None,
) -> str:
    """Search the knowledge base for relevant document chunks.

    Use when the user asks a question that requires retrieving information
    from indexed documents. Returns matching chunks with scores and metadata.
    """
    result = await search_service.search(
        query=query, top_k=top_k, threshold=threshold, collection=collection,
    )
    if result["total_results"] == 0:
        return "No relevant documents found."

    lines = [f"Found {result['total_results']} results ({result['search_time_ms']}ms):"]
    for i, r in enumerate(result["results"], 1):
        lines.append(
            f"\n--- Result {i} (score: {r['score']}, doc_id: {r['document_id']}) ---\n"
            f"{r['content']}"
        )
    return "\n".join(lines)
```

**关键细节**：
- `description`（docstring）告诉 LLM **什么时候用**这个工具
- `args_schema` 告诉 LLM **怎么用**（参数类型、默认值、描述）
- 返回值是**字符串**（LLM 只理解文本）

### 2.2 get_knowledge_base_stats（无参数工具）

```python
@tool  # 没有 args_schema → LLM 知道这个工具不需要参数
async def get_knowledge_base_stats() -> str:
    """Get statistics about the knowledge base.

    Use when the user asks about document counts, chunk counts, available
    collections, or the last time documents were indexed.
    """
    result = await stats_service.get_stats()
    lines = [
        "Knowledge Base Statistics:",
        f"- Total documents: {result['total_documents']}",
        f"- Total chunks: {result['total_chunks']}",
        f"- Vector store: {result['vector_store_type']}",
        f"- Last updated: {result['last_updated'] or 'N/A'}",
    ]
    for col in result.get("collections", []):
        lines.append(
            f"- Collection '{col['collection_name']}': "
            f"{col['document_count']} docs, {col['chunk_count']} chunks"
        )
    return "\n".join(lines)
```

### 2.3 ingest_text（文本录入工具）

```python
class IngestTextInput(BaseModel):
    text: str = Field(..., description="Text content to ingest")
    title: str = Field(..., description="Document title")
    author: str | None = Field(default=None, description="Document author")
    collection: str | None = Field(default=None, description="Target collection")

@tool(args_schema=IngestTextInput)
async def ingest_text(
    text: str, title: str, author: str | None = None, collection: str | None = None,
) -> str:
    """Ingest text content as a new document into the knowledge base.

    Use when the user wants to save information, add a note, or store text
    content for future retrieval.
    """
    content_bytes = text.encode("utf-8")
    filename = title if title.endswith(".txt") else f"{title}.txt"

    result = await upload_service.upload(
        file_content=content_bytes, filename=filename,
        mime_type="text/plain", author=author, collection=collection,
    )
    return (
        f"Successfully ingested '{result['filename']}' "
        f"(doc_id: {result['document_id']}, chunks: {result['chunk_count']}, "
        f"duplicate: {result['is_duplicate']})."
    )
```

## 3. create_tools 工厂函数

### 3.1 设计

```python
def create_tools(search_service, stats_service, upload_service) -> list:
    """工厂函数：将服务包装为 LLM 工具列表"""
    # 返回工具列表，供 AgentService 绑定到 LLM
    return [search_knowledge_base, get_knowledge_base_stats, ingest_text]
```

**为什么用工厂函数而不是直接定义？**

因为工具依赖 `search_service`、`stats_service`、`upload_service` 这些运行时实例。工厂函数通过闭包捕获这些依赖，避免使用全局变量。

### 3.2 闭包捕获依赖

```python
def create_tools(search_service, stats_service, upload_service):
    @tool(args_schema=SearchToolInput)
    async def search_knowledge_base(query, top_k=5, threshold=0.7, collection=None):
        # ↑ search_service 是外层函数的参数
        # 内层函数通过闭包"记住"了它
        result = await search_service.search(query=query, ...)
        ...

    return [search_knowledge_base, ...]
```

## 4. 工具的返回值格式：让 LLM 看得懂

### 4.1 格式原则

LLM 收到的是纯文本。要让它能"理解"工具结果，返回值必须：

- **结构化**：用换行、编号、分隔符
- **简洁**：去掉冗余信息，只保留关键信息
- **可操作**：告诉 LLM 这里有多少结果、每个结果是什么

```python
# ✅ 好的返回值（LLM 一看就懂）
"""
Found 5 results (search took 45ms):

--- Result 1 (score: 0.95, doc_id: abc-123) ---
RAG（Retrieval-Augmented Generation）是检索增强生成的缩写...

--- Result 2 (score: 0.87, doc_id: def-456) ---
RAG 结合了信息检索和文本生成两种技术...
"""

# ❌ 差的返回值（LLM 看不懂）
"""
<SearchResult object at 0x7f8b...>
"""
```

### 4.2 空结果的特殊处理

```python
if result["total_results"] == 0:
    return "No relevant documents found in the knowledge base."
```

让 LLM 明确知道"没有找到"，而不是返回一个空的 `Found 0 results`，后者可能让 LLM 困惑。

## 5. 实践：添加新工具

### 需求：添加"删除文档"工具

```python
class DeleteDocumentInput(BaseModel):
    doc_id: str = Field(..., description="Document ID to delete")
    collection: str | None = Field(default=None, description="Collection name")

@tool(args_schema=DeleteDocumentInput)
async def delete_document(doc_id: str, collection: str | None = None) -> str:
    """Delete a document from the knowledge base by its document ID.

    Use when the user explicitly asks to delete or remove a specific document.
    Only use this tool when the user provides a clear document ID or
    confirmation to delete.
    """
    deleted = await vector_store.delete([doc_id], collection)
    if deleted > 0:
        await dedup_service.mark_deleted(doc_id)
        return f"Successfully deleted document {doc_id} ({deleted} chunks removed)."
    return f"Document {doc_id} not found or already deleted."
```

### 注册到工厂函数

```python
def create_tools(search_service, stats_service, upload_service, vector_store, dedup_service):
    # ... 其他工具
    return [search_knowledge_base, get_knowledge_base_stats, ingest_text, delete_document]
```

### Agent 对话效果

```
用户：删除 doc_123 这份文档
Agent：[调用 delete_document(doc_id="doc_123")]
Agent：已成功删除文档 doc_123（共 15 个 chunks）。
```
