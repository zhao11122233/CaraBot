## 1. 两种去重场景

### 场景一：完全重复（同内容上传两次）

```
第一次上传 report.pdf (hash=abc123...)
  → 解析 → 切块 → 嵌入 → 存入向量库 → 记录元数据

第二次上传 report.pdf (hash=abc123...)
  → 计算哈希 → 发现已存在 → 直接返回已有记录（短路，不再处理）
```

### 场景二：增量更新（同文件名，内容变更）

```
第一次上传 policy.pdf (filename="policy.pdf", hash=aaa111...)
  → 正常入库

第二次上传 policy.pdf (filename="policy.pdf", hash=bbb222...)  ← 不同哈希！
  → 软删除旧记录（aaa111）
  → 删掉旧向量
  → 正常入库新版本（bbb222）
```

## 2. SHA256 哈希计算

### 2.1 为什么用 SHA256 而非 MD5？

| 算法 | 输出长度 | 碰撞风险 | 速度 |
|------|---------|---------|------|
| MD5 | 128 bit | 已知碰撞攻击 | 快 |
| SHA1 | 160 bit | 已知碰撞攻击 | 中 |
| **SHA256** | 256 bit | 实际不可能碰撞 | 中 |

文档去重场景下，SHA256 是行业标准。

### 2.2 实现

```python
import hashlib

@staticmethod
def compute_hash(content: bytes) -> str:
    return hashlib.sha256(content).hexdigest()
    # 输入：文件二进制内容
    # 输出：64 个十六进制字符的字符串
    #   例："a1b2c3d4e5f6...7890"（共 64 字符）
```

## 3. DedupService 完整分析

### 3.1 架构

```
DedupService
  │
  ├── compute_hash(content) → str           # 纯函数，计算 SHA256
  │
  ├── check_duplicate(hash) → DocumentRecord | None  # 按哈希查重
  │     └── SELECT * FROM documents WHERE file_hash = ? AND status = 'active'
  │
  ├── find_by_filename(filename) → DocumentRecord | None  # 查旧版本
  │     └── SELECT * FROM documents WHERE filename = ? AND status = 'active' ORDER BY created_at DESC
  │
  ├── register_document(...) → DocumentRecord   # 登记新文档
  │     └── INSERT INTO documents (...)
  │
  ├── mark_deleted(doc_id) → None              # 软删除
  │     └── UPDATE documents SET status = 'deleted' WHERE id = ?
  │
  └── 统计方法（get_total_documents, get_total_chunks, get_latest_timestamp）
```

### 3.2 哈希查重

```python
async def check_duplicate(self, file_hash: str) -> DocumentRecord | None:
    async with self._session_factory() as session:
        result = await session.execute(
            select(DocumentRecord)
            .where(DocumentRecord.file_hash == file_hash)
            .where(DocumentRecord.status == "active")     # ← 只查活跃记录
            .limit(1)
        )
        record = result.scalar_one_or_none()
        if record:
            logger.info("Duplicate detected: hash=%s, doc_id=%s", file_hash[:16], record.id)
        return record
```

**关键**：必须加 `status == "active"` 过滤条件，否则软删除的旧记录也会被匹配。

### 3.3 增量更新检测

```python
async def find_by_filename(self, filename: str) -> DocumentRecord | None:
    async with self._session_factory() as session:
        result = await session.execute(
            select(DocumentRecord)
            .where(DocumentRecord.filename == filename)
            .where(DocumentRecord.status == "active")
            .order_by(DocumentRecord.created_at.desc())
            .limit(1)
        )
        return result.scalar_one_or_none()
```

## 4. 在 UploadService 中的完整去重流程

```python
async def upload(self, file_content, filename, mime_type=None, author=None, collection=None):
    # ① 校验文件大小
    file_size = len(file_content)
    if file_size > self._settings.max_file_size:
        raise FileTooLargeException(...)

    # ② 计算哈希
    file_hash = self._dedup_service.compute_hash(file_content)

    # ③ 完全重复检测
    existing = await self._dedup_service.check_duplicate(file_hash)
    if existing is not None:
        # 一模一样，直接返回，跳过所有后续处理
        return {
            "document_id": str(existing.id),
            "filename": existing.filename,
            "file_hash": existing.file_hash,
            "file_size": existing.file_size,
            "chunk_count": existing.chunk_count,
            "is_duplicate": True,
            "message": "File already indexed.",
        }

    # ④ 增量更新检测（同文件名、不同哈希）
    old_record = await self._dedup_service.find_by_filename(filename)
    if old_record is not None:
        # 删旧向量
        await self._vector_store.delete([str(old_record.id)], col_name)
        # 软删除旧记录
        await self._dedup_service.mark_deleted(str(old_record.id))

    # ⑤ 解析 → 切块 → 嵌入 → 存向量库 → 登记新记录
    chunks = await self._doc_processor.load_and_split(file_content, filename, mime_type)
    doc_id = str(uuid.uuid4())
    texts = [chunk.page_content for chunk in chunks]
    embeddings = await self._embedding_service.embed_documents(texts)

    for chunk in chunks:
        chunk.metadata["document_id"] = doc_id
        chunk.metadata["filename"] = filename
        chunk.metadata["file_hash"] = file_hash

    chunk_ids = await self._vector_store.add_documents(chunks, col_name, embeddings)

    await self._dedup_service.register_document(
        filename=filename, file_hash=file_hash, file_size=file_size,
        mime_type=mime_type, chunk_count=len(chunks),
        collection_name=col_name, author=author, doc_id=doc_id,
    )

    return {
        "document_id": doc_id,
        "is_duplicate": False,
        "message": "Document updated successfully (incremental update)."
            if old_record else "Document processed successfully.",
    }
```

### 决策树

```
上传文件
  │
  ├── 哈希已存在（status=active）?
  │     └── YES → 完全重复，短路返回
  │
  ├── 同文件名存在（status=active）?
  │     └── YES → 增量更新：删旧向量 + 软删旧记录 + 处理新文件
  │
  └── 全新文件 → 正常入库
```

## 5. 软删除：不丢数据的删除

### 5.1 实现

```python
async def mark_deleted(self, doc_id: str) -> None:
    uid = UUID(doc_id)
    async with self._session_factory() as session:
        await session.execute(
            update(DocumentRecord)
            .where(DocumentRecord.id == uid)
            .values(status="deleted", updated_at=datetime.now(timezone.utc))
        )
        await session.commit()
```

### 5.2 好处

- **可恢复**：改回 `active` 就能恢复（虽然向量数据已删除）
- **可审计**：保留完整的操作历史
- **可追溯**：知道某个文件名曾经被哪些哈希对应过

### 5.3 查询必须过滤 status

```python
# ✅ 所有业务查询都要加 status == "active"
select(DocumentRecord).where(DocumentRecord.status == "active")

# ❌ 不加过滤会查到已删除的记录
select(DocumentRecord)
```
